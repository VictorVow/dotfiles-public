# Self-Hosted

> Copied from the private installs repo (`docs/system/self-hosted-readme.md`) for this public mirror. Relative links below point into a private `Self-Hosted/` monorepo that isn't published — they're kept for context, not navigation. Domains and IPs are placeholder-rewritten. The companion doc is [1-COMMON.md](1-COMMON.md) (the shared-infrastructure README).

Index of the self-hosted service repos. This directory is **not** a git repo itself; each subdirectory (or each sub-subdirectory, for grouped projects) is its own repo.

For the cross-repo architecture (shared Tailscale/Headscale tailnet, the shared Caddy edge on lord-ubuntu, the `node-services.yml` registry, and the `just` deploy orchestrator) read **[1-COMMON.md](1-COMMON.md)** first. Then read the README of the specific repo you're working on.

## Conventions

- Each service is an Ansible `deploy.yml` (usually plus `docker-compose.yml`) that imports `../1-COMMON/common.yml`. The dev shell is the shared deploy toolchain in `1-COMMON/flake.nix`, loaded by each repo's `.envrc` (`use flake ../1-COMMON`); repos that need extra tools keep a `flake.nix` with only those extras. Secrets live in a gitignored `.env`/`inventory.yml` (copy from the `*.example` files).
- Almost everything runs on the home server **lord-ubuntu** (`ssh lord@lord-ubuntu`, tailnet IP `100.x.x.x`) behind one shared Caddy edge. Services are **tailnet-only** at `https://<name>.device.example.com`. The subdomain → container mapping is in `1-COMMON/node-services.yml`.
- Deploy/redeploy: `cd 1-COMMON && just deploy <dir>`. Onboard a new service: add it to `node-services.yml`, then `just onboard <dir>`.
- Backup state of each lord-ubuntu service (data paths): `1-COMMON/STATE.md`.
- Grouped projects (e.g. `Suwayomi/`) hold a `*-deploy` repo next to the upstream forks and Android WebView wrappers it builds from. The `*-deploy` repo is the one that deploys.
